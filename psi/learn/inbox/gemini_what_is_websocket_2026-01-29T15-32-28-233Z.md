What is WebSocket?

WebSocket is a communication protocol that provides a full-duplex, persistent connection between a client (like a web browser) and a server.

Unlike traditional HTTP, which is a "request-response" system where the client must always ask for data first, WebSockets allow for a continuous, two-way flow of information. Once the connection is established, either the client or the server can send data at any time without waiting for the other to ask.

Key Features

Full-Duplex: Both parties can send and receive data simultaneously.

Persistent Connection: The connection stays open (kept alive) until either the client or the server chooses to close it.

Low Overhead: After the initial handshake, the data packets (frames) are very small, reducing the bandwidth used compared to repeated HTTP headers.

Real-Time: It is the industry standard for applications that require instant updates.

How It Works: The Handshake

WebSocket starts as a standard HTTP request. This is done to ensure compatibility with existing web infrastructure (like firewalls and proxies).

The Request: The client sends an HTTP "Upgrade" header to the server, asking to switch to the WebSocket protocol (ws:// or wss://).

The Response: If the server supports it, it sends back a 101 Switching Protocols status code.

The Connection: The HTTP connection is replaced by a WebSocket connection over the same TCP/IP port.

Why use it?
Use Case	Why WebSocket?
Chat Apps	Messages need to appear instantly for all users without refreshing.
Live Sports/Stocks	Data changes every second; polling HTTP would be too slow and heavy.
Gaming	Multiplayer games require ultra-low latency to sync player movements.
Collaborative Tools	Apps like Google Docs or Figma need to show cursor movements and edits in real-time.
Why? (The Context)

Before WebSockets, developers used "Long Polling," where the browser would repeatedly ask the server "Do you have new data yet?" and the server would hold the request open until it did. This was inefficient and put a high load on servers. WebSocket solves this by letting the server "push" data the moment it becomes available.

Note: Use wss:// (WebSocket Secure) instead of ws:// in production. It uses TLS/SSL encryption, making it much harder for attackers to intercept or tamper with your real-time data.
