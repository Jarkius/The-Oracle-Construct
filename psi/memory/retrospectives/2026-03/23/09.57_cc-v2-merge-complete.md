## Key Code Changes

1. **SSE line-count tracking** (`stream.ts`): Replaced `getFileSize` + byte-offset subtraction with `getLineCount` + `allLines.slice(lastLineCount)`. Eliminates UTF-8 multi-byte bugs entirely.

2. **DB_PATH absolute** (`core.ts`): `"./agents.db"` → `join(PROJECT_ROOT, "agents.db")`. Also fixed `LOCK_PATH`. Both now resolve correctly regardless of cwd.

3. **kill-orphans safety** (`daemons.ts`): Added `if (pid === process.pid) continue` on both Windows (taskkill) and Unix (process.kill) branches.

4. **Dashboard compact summary** (`daemon-card.ts`): New `renderDaemonSummary()` renders colored dots + names in a horizontal flex row — contrasts with full control cards on Services page.

## Architecture Decisions

- **Line-count over byte-offset for SSE**: Simpler, correct for all encodings, slightly more I/O (reads whole file each poll). Acceptable tradeoff for a monitoring dashboard.
- **Fast-forward merge**: Clean linear history since feature branch was based on latest main. No merge commit needed.
- **Slash commands as thin loaders**: Each `.claude/commands/X.md` just says "Read .agent/workflows/X.md and follow it." Keeps definitions in one place, commands are pointers.

## Honest Feedback

**Friction 1: Context compaction artifacts.** This session resumed from the 8th+ compaction of a 5-day mega-session. The compaction preserved facts but lost nuance — I had to re-read the handoff and plan to understand what was pending. The handoff system works, but it shouldn't be needed within a single logical session. The real fix is shorter sessions with clean boundaries, not better compaction.

**Friction 2: Background agent output format.** The task notification includes the full result text, but the output files are single-line stubs. This means I can only access results from the notifications, not by re-reading files. If I needed to resume later and re-read agent output, I couldn't. The agent result should be persisted in a readable format.

**Friction 3: Slash command loss was silent.** 43 commands disappeared during restructuring and nobody noticed until the user tried `/smith` and got nothing. There's no validation that checks "are all expected slash commands registered?" A pre-merge checklist or CI check would catch this class of error — missing integration points after file moves.

## Lessons Learned

1. **Verify agent diffs before committing** — Background agents are powerful but not infallible. Read every diff, understand the change, then commit.
2. **Restructuring severs wiring** — Moving files preserves content but breaks integration points (slash commands, imports, hooks). Trace all callers before moving.
3. **Short decisive sessions beat marathon sessions** — 10 focused minutes accomplished what could have been another 2-hour sprawl.
