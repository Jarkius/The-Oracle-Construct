## Architecture Decisions

1. **Fix readers, not writers** — Recap scripts searched wrong paths; data was always in the right place. Changed recap to read from where data lives, not where it assumed.
2. **Piper via pip, not binary** — `piper-tts==1.4.1` in `.venv/` instead of standalone binary. Cross-platform, version-managed, same ONNX models.
3. **Safe_play abstraction** — Single function that routes to afplay (macOS), PowerShell SoundPlayer (Windows), aplay (Linux). All voice scripts use it.
4. **bc→awk** — `bc` doesn't exist on Windows. `awk` is universal. Float arithmetic: `awk "BEGIN{printf \"%.1f\", $DURATION + 1.5}"`.
5. **sox→ffmpeg fallback** — Smith's bass boost: try `sox`, fall back to `ffmpeg -af bass`. Both produce same result.

## Honest Feedback

1. **The planning cycle was too long.** Two full plan iterations with deep exploration agents before a single line of code changed. The heartbeat.log had "Module not found" — that was the entire diagnosis in one line. Twenty minutes of multi-agent exploration to find what one `cat` would have shown. The ultrathink pass was valuable, but the first pass should have been more targeted: read the error logs first, explore the architecture second.

2. **Agent dispatching needs discipline.** Eight agents were dispatched across the session. Some produced 3,000+ word reports that were 70% redundant with each other. The Smith audit and Neo audit both found the same EVENT_WRITER bug independently. Two focused agents (one for paths, one for observability) would have been faster and cheaper. More agents ≠ more insight.

3. **Session scope crept significantly.** Started with "validate voice and memory on Windows" — ended with platform abstraction, observability overhaul, DB migration, recall pipeline rewrite, oracle-skills-cli learning, and adaptive voice AI. Each addition was justified in the moment, but the cumulative context load means this deep retro is happening at 80% context usage. The forward handoff should have been written at 13:00, not 14:20.

## Lessons Learned

1. **Read error logs before launching explorers** — `daemon-logs/heartbeat.log` had the answer. One file, one line, total clarity.
2. **Cascading failures hide behind silence** — No alerts ≠ no problems. Verify the monitor itself works.
3. **Cross-platform = test bash, not just TypeScript** — All breakage was in shell scripts, not in the application code.
4. **Same ONNX models work everywhere** — Platform barrier is in the shell, not the neural network.
5. **Sibling codebases hold patterns** — oracle-skills-cli's compiler, profiles, and version injection are ready to adopt.
