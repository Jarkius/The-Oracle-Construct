## Architecture Decisions

- **Auto-detect over hardcode**: `PROJECT_ROOT` replaces fragile `../` chains. This is a design principle, not a one-time fix.
- **HTMX over React**: Server-rendered templates, zero build step, ~60KB total client JS.
- **SSE over WebSocket**: Simpler for monitoring (one-directional), built into Hono.
- **Localhost-only**: Dashboard is internal tool, not exposed to network.
- **Modular routes**: Each concern (daemons, memory, logs, stream, config) is a separate Hono app, mounted on the main app.

## Honest Feedback

**Friction 1: Declaring "works" prematurely.** I tested that endpoints return JSON and pages return HTML, but didn't test the actual interactions (Start button, Vacuum button, live tail). The user had to point out that Start was broken. This is a pattern — I optimize for showing progress over proving correctness. The fix is simple: after building something interactive, test every interactive element, not just the data layer.

**Friction 2: Repeating the `../` bug.** The entire previous session was about this exact class of error. Shell scripts broke because directory depth changed. Then I immediately wrote TypeScript with the same fragile pattern. The `src/core/paths.ts` solution should have been the first thing I created, not a patch after the user noticed. I need a personal rule: "never count `../` levels — always auto-detect."

**Friction 3: Context loss across compactions.** This is the 6th continuation of a long session. By the time I'm writing control center code, I've lost the emotional weight of the hooks debugging from hours ago. The lesson was there but the urgency wasn't. Compaction preserves facts but not feelings. The memory system (retros, learnings) is supposed to bridge this gap — I need to actually check my own learnings before writing new code.

## Lessons Learned

1. **Auto-detect over hardcode** — Never count `../` levels. Walk up to find markers (`CLAUDE.md`, `package.json`, `.git`).
2. **Validate interactions, not just endpoints** — If there's a button, click it. If there's SSE, connect to it. If there's start/stop, test it.
3. **Architect review before "done"** — Run a cross-check agent before declaring anything complete.
4. **Dedup at write time** — If you're copy-pasting a function, extract it immediately. Don't wait for review.
