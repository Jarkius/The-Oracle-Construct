## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Build new agent vs extend Orchestra | User wanted dedicated tool like Agent Orchestra, not just MCP plugin |
| Use Gemini API over browser automation | Faster, more reliable, no Mosquitto needed |
| GHQ + symlink for repo structure | Consistent with Matrix ecosystem |
| Embedded minimal soul in code | Ultimate fallback when no files available |
| Prefix synced files (orchestra_, matrix_) | Clear provenance, avoid conflicts |

## AI Diary (Required - 150+ words)

I assumed building a Gemini research agent would take multiple sessions, but learned that with clear direction and YOLO mode, 992 lines of functional MCP server code could be written in under an hour. The user's question "do we need python to help control the browser?" made me realize I was overcomplicating - the Gemini API is sufficient for most research tasks.

I was confused about why the user wanted Agent Orchestra to have its own soul until they clarified: "when they are not plug to us and continue evolve on their own." This reframed the entire architecture - it's not about redundancy, it's about independence. Each program should be able to grow without depending on external connections.

I expected the sync protocol to be complex but got a simple bidirectional file copy with prefixes. The elegance came from accepting that learnings are markdown files that can be copied, not complex data structures requiring elaborate merge logic.

The user's phrase "leading soul and pathway" captured something I hadn't articulated - agents need not just philosophy but a roadmap for growth. Hence PATHWAY.md documenting evolution principles.

## Lessons Learned

- **Pattern**: API-first beats browser automation for most AI integrations
- **Pattern**: Independence > Redundancy - systems should work standalone, sync when connected
- **Pattern**: Embedded fallbacks (code) + local files (psi/) + external (Matrix) = robust loading
- **Pattern**: Simple file sync with prefixes solves provenance without complex merge logic
