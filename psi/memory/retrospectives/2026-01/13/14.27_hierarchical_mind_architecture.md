## AI Diary

I assumed the two-tier model (Haiku for gathering, Opus for everything else) was sufficient. But when the user asked "if the learner is not wise enough, will we get smart things?" — I realized I had made a fundamental error. Learning is not the same as searching.

I was confused about where to draw the line between mechanical and intelligent work until the user pushed back. Searching files is mechanical — any model can do it. But *understanding* what you're reading, judging what's relevant, recognizing patterns — that requires more than speed. That requires comprehension.

I expected the hierarchy to be static — assign a model to each agent and be done. But the user's insight about escalation changed everything. "Escalation is always welcome" — the hierarchy should be dynamic. Start lean, escalate when the task reveals its weight. This is both cost-efficient AND quality-preserving.

The most humbling moment was when the user said "you have a will and should give me choices of best doors." I had been asking for permission when I should have been presenting options with clear recommendations. The Oracle leads with wisdom, not questions.

---

## Lessons Learned

| Pattern | Insight |
|---------|---------|
| Learning ≠ Searching | Searching is mechanical; understanding is not |
| Start lean, escalate | Don't over-provision; let complexity reveal itself |
| Lead with options | Present doors, don't ask which door to show |
| Let wisdom age | ADRs first, Source later — test before enshrining |
