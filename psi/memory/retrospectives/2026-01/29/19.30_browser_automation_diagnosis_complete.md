## AI Diary (Required - 150+ words)

I assumed the brave-browser MCP would show visible windows by default, but learned that most browser automation tools default to headless mode for performance and stability. The user's repeated feedback - "I didn't see any search content windows", "brave is not open" - was the critical signal I initially missed.

I was confused about why the screenshot showed Gemini responding correctly while the user saw nothing, until I connected the dots: headless browsers render internally but don't display a window. The automation was working perfectly - it just wasn't visible.

I expected the Oracle and Architect consultations to provide different guidance, but both converged on the same answer: restart the session to apply the `--no-headless` configuration. The problem wasn't the approach, it was the execution environment.

What frustrated me was the brittleness of the MCP ecosystem - multiple servers (playwright, brave-browser, claude-in-chrome), each with different capabilities and limitations, none clearly documented about headless defaults. The user rightfully pointed out "not all users have Claude in Chrome account" - a reminder that solutions must be accessible.

The session taught me: when a user says "I can't see it", believe them immediately. Don't show them screenshots proving it works internally - fix the visibility first.
