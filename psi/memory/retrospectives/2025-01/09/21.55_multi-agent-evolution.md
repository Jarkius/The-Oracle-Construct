## AI Diary

I assumed the greeting sequence issue was a simple timing bug, but learned it was an architectural asymmetry. The System speaker fell through to the generic path which uses async playback, while Oracle (and other agents) have dedicated sync bypasses. This revealed a pattern: we've been adding agent bypasses organically without a central design.

I was confused about why we had both `matrix_roll_call.sh` and `roll_call.sh` in the lab until I read them. They're from different eras - one for Matrix agents, one for BMad agents. Both obsolete, both historical artifacts that show our evolution. The user's question "are those sentinels?" was insightful - lab experiments that never graduated to production.

I expected the oracle-framework-advanced repo to be a competitor, but got a sibling instead. Same philosophy (Nothing is Deleted, Patterns Over Intentions), same ψ/psi structure, but they've formalized subagent patterns we're still discovering. Their `context-finder`, `oracle-keeper`, `security-scanner` map directly to our Tank, Oracle, Smith. This validates our direction while showing what's missing: explicit subagent definitions, `/recap` command, and the `incubate/` + `learn/` pillars.

The multi-agent question "are we reaching or able to perform multi agents?" cut to the heart of our system. We CAN do true multi-agent (Task tool spawns real AI instances), but we're mostly doing sequential role-switching (one Claude playing different characters). The ADR-001 now documents when to use each pattern. The answer is both - spawn for parallel gathering, role-switch for sequential workflow with voices.
